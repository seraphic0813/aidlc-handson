# DeskFlow

社内問い合わせの登録と窓口対応を練習する、1台のPC向けローカルアプリです。React・TypeScriptの4画面と、Node標準HTTP・SQLiteを1プロセスで動かします。初回だけ架空の問い合わせ10件を投入します。

## 導入と検証

Node **24.14以上、25未満**を使用します。`node:sqlite`はNodeの開発中APIです。依存は具体的な版に固定し、lockfileに記録しています。グローバル導入は不要です。以下はワークスペースのルートで実行します。

```sh
npm --prefix deskflow ci
npm --prefix deskflow run typecheck
npm --prefix deskflow run lint
npm --prefix deskflow run format:check
npm --prefix deskflow run build
npm --prefix deskflow run test:unit -- --project u1-deskflow
npm --prefix deskflow run test:coverage -- --project u1-deskflow
```

テストは`tests/u1-deskflow/`に限定し、専用の`deskflow/.local/verification/`だけを使用します。UI試験はDOM、保存・HTTP試験は実SQLiteと一時ループバックサーバーを使用します。カバレッジの母数は`src/`の全手書きTS/TSXで、型宣言、依存、生成物、設定とテストを除き、行80%以上を要求します。HTMLレポートは`deskflow/coverage/index.html`です。実ブラウザーのキーボード操作・200%拡大・画面全体2秒の確認は別途必要です。

## 起動・停止

本人の起動判断後に次を実行し、ブラウザーで`http://127.0.0.1:3000`を開きます。

```sh
npm --prefix deskflow start
```

停止は起動した端末のCtrl+Cです。正常停止してから同じコマンドで再起動すると、登録・対応内容を保持します。ポートのみ`DESKFLOW_PORT`で変更できます。PowerShellの例は`$env:DESKFLOW_PORT = '3001'`です。公開インターフェースにはバインドしません。同じPCの利用者がデータを共有するため、認証や複数利用者向けのアクセス制御は備えていません。

## 操作

入口から「登録」「一覧」を選びます。申請者名50、件名100、問い合わせ内容2000書記素以内、分類は任意です。前後の空白は除去し、内容の改行は保持します。受付番号は連番です。同じ受付キーの再送は同じ結果を返します。受付結果が不明な場合は入力を固定し、同じ内容を再送できます。

一覧は登録日時と番号の降順、20件ずつです。件名・内容・回答・申請者名・担当者名を全半角と大小文字をそろえて部分一致検索し、状況条件を併用できます。詳細から一覧に戻ると条件とページを保持します。

未対応→対応中→完了の順に変更します。完了には回答が必要で、担当者は未割当でも構いません。完了後は再開して編集します。再開は担当と回答を保持します。版競合では入力を保持し、最新内容を比較したうえで版を選び直します。未保存で移動すると確認します。通信の待機は10秒です。

変更要求の**JSON本文全体**をUTF-8で計測し、65536バイトを許可、65537バイト以上を拒否します。結合文字やJSONエスケープにより書記素上限以内でも超過する場合があり、画面でも送信と同じ表現を検査します。拒否時は入力を保持します。

## 保存・ログ・保守

保存先はこのプロジェクトの`deskflow/.local/`固定です。DBは`data/deskflow.sqlite`、ログは`logs/`、コピーは`backups/`、排他と停止記録は`state/`です。これらとnode_modules・dist・coverageはGit対象外です。ログは本文・回答・氏名・検索語・受付キーを記録せず、1MiBで切り替えて現行1ファイルと過去3世代を保持します。

**通常アプリを正常停止し、本人がコピー実行を判断してから**以下を実行します。

```sh
npm --prefix deskflow run backup
```

停止記録と排他を確認し、既存ファイルを上書きせずコピー・整合性検査・メタ情報記録を行います。出力されたコピーのファイル名で検査できます。

```sh
node deskflow/dist/server/server/maintenance-cli.js inspect コピー名.sqlite
```

復旧は内容・メタ情報を確認し、本人が対象を選んだ後に実行します。対象はbackups内のファイル名のみです。原本を別名で保全してから置き換えます。

```sh
npm --prefix deskflow run restore -- コピー名.sqlite --confirm
```

排他記録が残った場合は自動削除しません。実行中プロセスがないことを確認し、異常終了の原因とDBの整合性を確認してから管理者が判断してください。稼働中DBの直接コピー、手動SQL編集、同期ソフトとの共有は避けてください。検証テストでのコピー・復旧は専用データに限り、利用者データの保守実施を意味しません。

性能確認用の独立100件の準備例は`workflow.test.ts`にあります。通常データとは別のメモリーDBへ登録し、検索・20件ページ・同時刻ソートを検証します。画面全体の計測には別途本人判断によるブラウザー確認が必要です。
