## 目的・利用者・成功条件

| ID | 決定内容 | 根拠 |
|---|---|---|
| D-01 | 中心課題は、過去の問い合わせと回答を見つけにくく、同じ調査を繰り返すこと | 目的整理Q1 |
| D-02 | 最優先の利用者は窓口担当者、追加の関係者は対応漏れを確認したい窓口責任者 | 目的整理Q2・Q4 |
| D-03 | 未対応と担当者の特定、受付から完了までの確認、過去の問い合わせと回答の発見の3つを成功条件とする | 目的整理Q3 |
| D-04 | 架空データだけを使い、企画からローカル運用までを一工程ずつ体験する | 最初の依頼、目的と成功条件 |

## 対象範囲・優先順位

| ID | 決定内容 | 根拠 |
|---|---|---|
| D-05 | 社員本人がIT窓口への問い合わせを登録し、窓口担当者が対応する | 対象範囲Q1・Q2 |
| D-06 | 初回の必須範囲は登録、担当・状況の把握と更新、完了と回答記録、過去の検索・参照 | 目的整理Q3、対象範囲Q3、IB-01〜IB-04 |
| D-07 | 添付ファイル、担当者別集計、模擬メール通知は将来の検討へ回す | 対象範囲Q3、IB-05〜IB-07 |
| D-08 | 実在アカウントのログインと社内認証基盤との接続は対象外 | 目的整理Q5、対象範囲Q1 |
| D-09 | 実データの使用、AWSへのデプロイ、外部公開は対象外 | 最初の依頼、目的と成功条件 |
| D-10 | 登録 → 担当・状況の更新 → 完了 → 過去の検索の順に確認する | 対象範囲Q4 |
| D-11 | 期限は設けず、一工程ずつ確認する | 対象範囲Q5 |

## 画面の構成

| ID | 決定内容 | 根拠 |
|---|---|---|
| D-12 | PCのブラウザーを主対象にする | 画面案Q1 |
| D-13 | 最初に社員と窓口担当者の入口を選ぶ。認証方式を決めるものではない | 画面案Q2 |
| D-14 | 一覧は全件を新しい順に表示し、未対応へ絞り込める | 画面案Q3 |
| D-15 | 一覧と同じ画面で過去の問い合わせを検索し、詳細で回答を読む | 画面案Q4 |
| D-16 | 一覧性を重視した簡潔な業務ツールとし、必要な案内とエラー説明を表示する | 画面案Q5 |

## 費用・準備・確認の進め方

| ID | 決定内容 | 根拠 |
|---|---|---|
| D-17 | 追加費用のかからないツール・構成で進める | 本工程Q1：A |
| D-18 | 必要な無料ソフトは、目的と導入内容を説明したうえで追加してよい | 本工程Q2：B |

| D-20 | レビューはadvisory、DepthとTest Strategyはstandardとする | 承認済みの計画 |

## 後工程で具体化する事項

- 入力項目、必須条件、文字数、状態名・状態遷移、検索対象、操作権限：要件整理・機能設計。
- 技術構成、データ保存方式、復旧の仕組み：ドメイン設計・品質設計・ローカル環境設計。
- 実装単位と具体的な作業の依存関係：実装単位整理。
- ローカルで動くことと成功条件の達成：実装・テスト・起動確認・運用演習。

上記は次の工程で決める対象であり、画面の仮表示を確定した要件へ読み替えない。
