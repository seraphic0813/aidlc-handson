# DeskFlow：本人が明示した制約

> 本人が明示した制約と本工程の回答を反映したもの。組織の推奨値を本人の独自制約として追加しない。本工程の承認前に共通の運用ルールへ反映しない。

## Mandated

- ALWAYS 架空データだけを使い、企画からローカル起動・ローカル運用までの演習を行う。
- ALWAYS 各工程の承認点で作業内容を説明し、本人の判断を待つ。
- ALWAYS 実装前のコード計画承認を維持する。
- ALWAYS 追加費用のかからないツール・構成で進める。
- ALWAYS 必要な無料ソフトを追加する前に、その目的と導入内容を説明する。
- ALWAYS 別の作業ブランチが必要になった場合は、作成前に本人へ相談する。
- ALWAYS ローカル操作はAIが操作内容とコマンドを説明して実行し、本人が結果を確認する進め方とする。

## Forbidden

- NEVER AWSへデプロイしたり、システムを外部公開したりする。
- NEVER 実在する問い合わせなどの実データを演習に使う。
- NEVER 初回の範囲に、実在アカウントによるログインや社内認証基盤との接続を含める。
- NEVER 初回の範囲に、添付ファイル・担当者別件数集計・模擬メール通知を自動的に追加する。
- NEVER 明示的な依頼なしにコミット・プッシュ・マージを行う。

## Sources

- 最初の依頼と承認済みの計画：架空データ・ローカル限定、工程ごとの本人判断、実装前のコード計画承認。
- [企画の引き継ぎ概要](../../ideation/approval-handoff/initiative-brief.md)：演習の境界と初回の範囲。
- [企画の回答](../../ideation/approval-handoff/approval-handoff-questions.md)：Q1=A（追加費用なし）、Q2=B（目的・導入内容の説明後に必要な無料ソフトを追加可能）。
- [対象範囲](../../ideation/scope-definition/scope-document.md)：実在アカウントのログイン・認証接続、初回に含めない追加機能。
- [本工程の回答](practices-discovery-questions.md)：Q1=A（別ブランチが必要な場合は相談）、Q4=A（AIが説明・実行し本人が結果を確認）。
- 本人が会話で提示したGlobal Codex Instructionsの「ファイル・Git操作」：コミット・プッシュ・マージは明示的な依頼がある場合に実施する。
