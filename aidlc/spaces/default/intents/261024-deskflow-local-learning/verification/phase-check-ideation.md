## 目的・範囲・機能候補・画面の対応

| 成功条件 | 初回の機能候補 | 画面・流れ | 整合性 |
|---|---|---|---|
| S1：未対応と担当者を特定する | IB-02：担当・状況の把握と更新 | W2の一覧・未対応の絞り込み、W3の対応欄 | 対応あり |
| S2：受付から対応完了までを確認する | IB-01：登録、IB-02：更新、IB-03：完了・回答記録 | W1で登録し、W2からW3へ進んで対応する | 対応あり |
| S3：過去の問い合わせと回答を見つける | IB-03：回答記録、IB-04：検索・参照 | W2で検索し、W3で回答を読む | 対応あり |

成功条件3件すべてに対象機能と画面の対応がある。初回の機能候補4件すべてに成功条件と画面の対応がある。これは文書上の対応関係の確認であり、実装やテストのカバレッジを表すものではない。

## 境界と関係者の一致

| 確認項目 | 結果 |
|---|---|
| 社員本人が登録し、窓口担当者が対応する | 範囲・機能候補・画面案で一致 |
| 窓口責任者の対応漏れへの関心 | 未対応の把握という成功条件と整合 |
| 添付ファイル・担当者別集計・模擬メール通知を初回に含めない | 初回の機能候補・画面・操作の流れで一致 |
| 架空データ・ローカル限定、実在アカウントと社内認証接続なし | 目的・対象範囲・画面案で一致 |
| AWSへのデプロイ・外部公開なし | 目的・対象範囲・引き継ぎ概要で一致 |
| 期限なし、一工程ずつ本人が判断 | 対象範囲と引き継ぎ概要で一致 |
| 追加費用なし、説明後に必要な無料ソフトを追加可能 | 本工程の回答と引き継ぎ概要で一致 |

## 実現性の裏付けと未実証事項

独立した実現性検証は承認済みの計画で省略しており、実現性評価書は存在しない。技術構成・保存方式もまだ選択していない。この段階で、実装済み・検証済み・動作保証済みとは判断しない。

| 対象機能 | 企画上の整理 | 後工程で確かめること |
|---|---|---|
| IB-01：登録 | 入力から受付へ進む範囲と画面案がある | 入力検証、保存、成功・失敗時の動作 |
| IB-02：担当・状況の把握と更新 | 一覧と詳細で扱う情報・操作の案がある | 状態遷移、更新、未対応の特定 |
| IB-03：完了と回答記録 | 詳細で完了と回答を扱う案がある | 完了条件、回答保存、再表示 |
| IB-04：過去の検索・参照 | 一覧から詳細で回答を読む経路がある | 検索対象と一致条件、結果の正しさ |

文書間で両立しない要求は検出しなかった。一方、各機能の技術実現性は未実証であり、上記の確認を要件整理・設計・実装・テストへ引き継ぐ。

## 引き継ぎ判定と本人確認

企画の整合性については移行を妨げる矛盾・機能の対応漏れは検出しなかった。技術の動作検証は後工程で行う条件で、引き継ぎを推奨する。

- [x] 目的・対象範囲・機能候補・画面の対応を確認した。
- [x] 未実証事項と後工程の確認対象を明示した。
- [x] 企画の確認・引き継ぎについて、本人の工程承認を得た。

本人の工程承認後、上記の未実証事項を引き継いで、開発・テスト・ローカル運用方針の整理へ進む。
