## Local Delivery Flow

独立したホスト型CIと配備パイプラインは対象外。ファイル名は工程の規定に従うが、内容はローカルで再実行する導入・検証・起動の順序である。Git操作や外部配備を工程承認の意味に含めない。

| 順 | 処理 | 計画するコマンド・方法 | 通過条件・本人判断 |
|---|---|---|---|
| 1 | 実装計画 | コード計画にファイル一覧、依存、順序、テスト指示と起動条件を記載 | 本人のApprove Planを待つ。計画だけで依存導入や実装を開始しない |
| 2 | 無料依存の導入 | 導入目的を説明し、実装初回にpackage.jsonとlockfileを確定 | プロジェクト内へ導入。Nodeの無断更新やグローバル追加をしない |
| 3 | 再現導入 | npm --prefix deskflow ci | lockfileどおりに導入できる。初回のlockfile生成前にci成功を主張しない |
| 4 | 型・静的確認 | npm --prefix deskflow run typecheck / lint / format:check | 型・lint・整形の失敗0件。TypeScriptのビルドだけで型確認を代用しない |
| 5 | 層ごとの実装と検証 | test-afterで各層を実装後、その単体・主要境界の結合テストを実行 | 登録、状態、Unicode、再送、競合、初期化、保存・ログ・保守、Reactの操作を確認 |
| 6 | 全計測対象のテスト | npm --prefix deskflow run test:coverage | 手書き実装TS/TSXの行カバレッジ80%以上、未実行ファイルも母数。除外理由を記録 |
| 7 | 配布用のビルド | npm --prefix deskflow run build | React配信物とNode実行物が生成され、欠けたimportや必要ファイルがない |
| 8 | 起動前の説明 | テスト・ビルド・監査結果、残る問題、待受先、保存先、起動コマンドを提示 | 本人のローカル起動判断を待つ |
| 9 | 起動と操作確認 | npm --prefix deskflow startを予定。正確なエントリーはコード計画で確定 | ループバック、初期10件、主要操作、キーボード、200%拡大、性能の確認 |
| 10 | 停止・再起動・保守 | READMEに再現手順を用意。正常停止確認、コピーと検査、本人判断後の復旧 | 演習用と検証用を分離。復旧対象を無断で切り替えない |

上記npmスクリプトは実装予定の契約名であり、現時点では未作成・未実行。具体的なテスト対象と実コマンドはunit-test-instructions.mdとコード計画に記載し、実行結果は後工程で報告する。自動の全検証コマンドはアプリの常時起動や復旧を含めず、有限時間で終了する構成とする。

## Test Scope and Failure Gates

| 確認 | 重点 | 失敗時 |
|---|---|---|
| 単体 | 文字・固定値・状態・未割当完了・検索条件 | ロジックを修正し対象テストを再実行 |
| 主要結合 | SQLite保存、受付再送、版競合、初回投入、一括取消 | 正式保存を確認するまで完了扱いしない |
| HTTP・配信 | Host/Origin、Content-Type、独自ヘッダー、本文上限、ルート脱出 | 入力拒否と保存値不変、配信境界を確認 |
| 追加受入条件 | JSON本文全体のUTF-8 65536/65537バイト、書記素数内の超過、付帯項目やエスケープ込み | 前者は他条件も満たす場合に許可、後者は413相当で拒否し入力を保持 |
| React | Atomic Designの役割、ラベル、入力保持、正常0件と失敗、未保存移動、競合回復 | 利用者に見える動作で確認し、実装構造だけのテストにしない |
| ログ・保守 | 容量、秘密や本文の非記録、排他・コピー検査・復旧保全 | 実データや演習正本を壊すテストをしない |
| カバレッジ | 全手書き実装、行80%以上 | 対象や下限を下げず必要なテストを追加 |

## Release and Rollback

| 項目 | ローカルでの扱い |
|---|---|
| 配備方式 | 停止して検証済みビルドへ置き換え、再起動するrecreate。無停止配備は行わない |
| 差し戻し | 新旧ビルドの互換性を確認し、停止後に前のビルドへ戻す。DBの自動巻戻しはしない |
| スキーマの変更 | 初回の定義を版付きで管理。不明な版は停止。将来の変更は互換性とバックアップを先に設計し、勝手に破壊的移行を追加しない |
| 環境昇格 | staging/prodなし。検証専用保存先で確認したビルドを、本人判断後に演習で使う |
| 秘密情報 | 認証キー・AWS資格情報を必要としない。依存取得の個人設定をソースへコピーしない |
| Git | コミット・プッシュ・マージは明示依頼時のみ |

## Dependency and Tooling Control

無料のReact・React DOM、TypeScript、ViteとReact用プラグイン、VitestとV8カバレッジ、React Testing Library・DOMテスト環境、ESLint・Prettier等を必要に応じてプロジェクト専用に導入する。具体的なパッケージ名と版はコード計画で絞り、使用目的・互換性・監査結果を記録する。依存監査で問題が見つかった場合は内容を説明し、無断で破壊的な自動修正や品質目標の引下げを行わない。

node:sqliteは記録したNode版で開発中APIであるため、保存境界をテストし、別のNode版で動くと無検証で主張しない。WindowsのChromeまたはEdgeの実際に使った版も確認結果へ残す。
