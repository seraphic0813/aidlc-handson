## Component Hierarchy

| 画面内の責任 | 表示入力 | 一時状態・発生する操作 |
|---|---|---|
| 共通枠 | ローカル演習の案内、ページ見出し | 入口への移動、未保存移動の確認、結果通知 |
| W0：入口選択 | 社員と窓口担当者の入口 | 社員はW1、窓口はW2へ移動 |
| W1：登録フォーム | 必須3項目、任意分類、検証制約 | 入力値、操作キー、送信内容、処理中、受付結果、別件登録 |
| W2：検索・一覧 | 検索語、状態、適用条件、件数、受付番号・件名・担当・状態 | 入力中の条件と適用済み条件、ページ、最新要求の識別、読込結果 |
| W3：内容・対応 | 受付情報、登録内容、担当・状態・回答、期待版 | 保存済み値と編集中の値、保存中、競合、再開、一覧へ戻る |

これらはDeskFlowInterface内の表示責任であり、追加のドメインコンポーネントや永続エンティティではない。

## Interaction and Validation

本人の[ローカル実行環境Q2=A](../infrastructure-design/infrastructure-design-questions.md)により、登録・対応保存等の送信JSON本文全体にはUTF-8で65536バイトの上限も適用する。文字数内でも超過する場合があることを入力説明に記載する。送信に使うJSONを同じ表現で計測し、超過時は入力を保持してデータ量の修正を案内する。管理側からの413相当の応答でも同じ案内と入力保持を行う。

画面側は文字数と固定値の入力補助を行い、正式な判定はInquiryManagementに委ねる。送信中は重複操作を抑え、完了前に成功と表示しない。登録成功後の確認表示から「別の問い合わせを登録する」で空のフォームに切り替える。

詳細は未対応・対応中だけ編集可能。完了中は担当と回答を参照表示し、再開操作で既存値を保つ。競合時の最新値と未保存入力は区別して保持し、見直して明示保存する。保存・入力エラーで入力を消さない。表示時点の値と異なる未保存入力がある場合は、アプリ内の移動で戻る・破棄して移動を選ばせる。ブラウザーの終了・再読込には利用可能な離脱確認を使い、自動復元は保証しない。

## User Feedback and Accessibility

読込中・保存中・成功・変更なし・入力不備・競合・保存失敗・結果不明・0件・対象なしを文字で区別する。入力欄は見えるラベル、エラーは欄との関連、結果は読み上げ可能な通知、操作は見えるフォーカスを持つ。失敗後はエラー概要または該当欄へ移動できる。キーボードだけで主要操作を行える構成とし、200%拡大では詳細の内容と対応を縦に並べて重なりを避ける。長文は折り返し、HTMLや記号は文字として表示する。

## Integration Boundary

論理的操作と入出力はfunctional-spec.mdのInternal Operations and Failure Resultsを参照。画面から保存先を直接更新しない。検索結果の応答順逆転を防ぎ、一覧へ戻る場合は適用条件を保って再取得する。通信プロトコル、実際の構成ファイル、ライブラリは後工程で決める。
