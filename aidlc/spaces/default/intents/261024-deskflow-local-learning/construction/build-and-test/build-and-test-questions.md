## Q1：ローカル起動と実ブラウザーでの検証へ進めますか？

A. 起動して検証を進める（推奨）。以下の操作をAIが実行し、結果を報告する。

- 通常起動は `npm --prefix deskflow start`。待受は `http://127.0.0.1:3000`。初回には `deskflow/.local/data/deskflow.sqlite` に架空10件、同じ `.local/` 内にログと状態記録が作られる。既存の演習DBがあれば初期化・上書きしない。
- 実ブラウザーで登録・検索・対応更新・完了・再開、キーボード操作と200%拡大を確認する。架空の検証問い合わせを登録・更新し、その番号を記録する。確認後は正常停止と再起動による保存保持を確認する。
- 性能測定では通常の10件を100件へ置き換えず、`deskflow/.local/verification/` 内に独立した検証用保存先を用意する。ビルド済みの同じアプリを検証用の起動処理から利用し、ループバックの別ポートで起動する。公開ビルドは既存の `deskflow/dist/client/` を参照し、製品コードや通常の保存設定は変えない。架空100件の基準状態で一覧・検索・登録・更新を各5回測定し、20回の個別値を記録する。各回の基準状態復元はAIが作成した専用データだけを対象にする。
- ビルドと既存の単体・結合・境界検証を本工程でも実行し、26件の詳細NFRと設計上の追加条件を、達成・未達・未確認に分けて記録する。実ブラウザーを操作できないなどの制約があれば未確認として報告する。
- 通常データのバックアップ実行と復旧先への切替は、この回答だけでは行わない。正常停止後に対象・コピー先・内容・影響を具体化して、別途判断を待つ。
